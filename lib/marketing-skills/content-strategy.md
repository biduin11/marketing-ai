# Content Strategy — фреймворки

## Searchable vs Shareable

Каждый контент должен быть searchable, shareable, или и то и другое. Приоритет в этом порядке — поисковый трафик — фундамент.

**Searchable-контент** ловит существующий спрос. Заточен под тех, кто активно ищет ответ.

**Shareable-контент** создаёт спрос. Распространяет идеи, вызывает обсуждение.

### Признаки хорошего searchable-контента
- Целится в конкретный ключевик или вопрос
- Точно попадает в поисковый интент
- Заголовки повторяют формулировки запросов
- Структура заголовков отражает паттерны поиска
- Ключевые слова в title, заголовках, первом абзаце, URL
- Исчерпывающее покрытие темы (не оставляет вопросов без ответа)
- Данные, примеры, ссылки на авторитетные источники
- Оптимизация под обнаружение AI/LLM: чёткое позиционирование, структурированный контент, консистентность бренда по всему вебу

### Признаки хорошего shareable-контента
- Начинается с неочевидного инсайта, оригинальных данных или контринтуитивного тезиса
- Бросает вызов общепринятому мнению с аргументацией
- Истории, которые вызывают эмоцию
- Контент, которым хочется поделиться, чтобы выглядеть умным или помочь другим
- Привязка к текущим трендам или новым проблемам
- Честный, уязвимый личный опыт, из которого другие могут извлечь урок

## Типы контента

### Searchable-типы

**Use-Case контент**
Формула: [персона] + [сценарий использования]. Целится в длинный хвост.
Примеры: «Управление проектами для дизайнеров», «Трекинг задач для разработчиков»

**Hub and Spoke**
Hub = обзорная страница по теме. Spokes = связанные подтемы.
```
/тема (hub)
├── /тема/подтема-1 (spoke)
├── /тема/подтема-2 (spoke)
└── /тема/подтема-3 (spoke)
```
Сначала создаётся hub, потом spokes. Активно перелинковываются.
Для большинства случаев достаточно обычного `/blog/название-поста` — отдельная hub/spoke-структура URL нужна только для крупных тем с несколькими уровнями глубины.

**Библиотеки шаблонов**
Высокоинтентные запросы + adoption продукта.
Целится в запросы вроде «шаблон маркетинг-плана», даёт самостоятельную ценность, показывает как продукт усиливает шаблон.

### Shareable-типы

**Thought Leadership** — формулирует то, что все чувствуют, но никто не называл словами; бросает вызов общепринятому с доказательствами.

**Data-Driven контент** — анализ собственных данных продукта (обезличенно), анализ публичных данных, оригинальные исследования.

**Expert Roundups** — 15-30 экспертов отвечают на один конкретный вопрос. Встроенная дистрибуция за счёт участников.

**Кейсы (Case Studies)** — структура: Проблема → Решение → Результаты → Ключевые выводы.

**Meta-контент** — закулисная прозрачность («Как мы получили первые $5к MRR», «Почему мы выбрали долг, а не инвестиции»).

## Контент-пиллары и топик-кластеры

Пиллары — 3-5 ключевых тем, которыми владеет бренд. Каждый пиллар порождает кластер связанного контента.

### Как определить пиллары
1. **От продукта**: какие проблемы решает продукт?
2. **От аудитории**: чему нужно научиться ЦА?
3. **От поиска**: какие темы имеют объём в нише?
4. **От конкурентов**: за что ранжируются конкуренты?

### Структура пиллара
```
Тема-пиллар (Hub)
├── Кластер подтем 1
│   ├── Статья A
│   ├── Статья B
│   └── Статья C
├── Кластер подтем 2
└── Кластер подтем 3
```

### Критерии хорошего пиллара
- Соответствует продукту/услуге
- Совпадает с тем, что важно аудитории
- Есть поисковый объём и/или интерес в соцсетях
- Достаточно широкий для множества подтем

## Keyword-исследование по стадиям воронки

### Awareness (осознание)
Модификаторы: «что такое», «как», «руководство по», «введение в»
Пример: «Что такое Agile-управление проектами», «Как провести стендап»

### Consideration (рассмотрение)
Модификаторы: «лучшие», «топ», «vs», «альтернативы», «сравнение»
Пример: «Лучшие инструменты управления проектами для удалённых команд», «Asana vs Trello vs Monday»

### Decision (решение)
Модификаторы: «цена», «отзывы», «демо», «пробный период», «купить»
Пример: «Сравнение цен на инструменты управления проектами», «Как выбрать тариф»

### Implementation (внедрение)
Модификаторы: «шаблоны», «примеры», «туториал», «как использовать», «настройка»
Пример: «Библиотека шаблонов проектов», «Пошаговый туториал по настройке»

## Источники идей для контента

**Keyword-данные** (Ahrefs, SEMrush, GSC): группировка в топик-кластеры, привязка к стадии воронки, определение search intent, поиск quick wins (низкая конкуренция + приличный объём + высокая релевантность), поиск пробелов (ключи, по которым ранжируются конкуренты, а ты нет).

**Транскрипты звонков** (продажи, поддержка): вопросы клиентов → FAQ/посты; боли → формулировки проблем; возражения → контент, закрывающий их заранее; языковые паттерны → voice of customer.

**Опросы**: открытые ответы (темы и формулировки), общие темы (если 30%+ упоминают — высокий приоритет), запросы на ресурсы, предпочтения по форматам.

**Форумные исследования** (Reddit, Quora, Indie Hackers, Hacker News, отраслевые Slack/Discord): топовые посты, вопросы и фрустрации в комментариях, апвоутнутые ответы — валидируют, что реально резонирует.

**Анализ контента конкурентов**: топ-посты (по комментариям/шерам), темы, которые покрывают повторно, пробелы, которые не покрыли, кейсы, структура контента (пиллары, категории, форматы).

**Продажи и поддержка**: частые возражения, повторяющиеся вопросы, паттерны в тикетах, success-стори, запросы фич и проблемы за ними.

## Приоритизация идей контента

Скоринг по четырём факторам:

**1. Customer Impact (40%)** — как часто тема всплывала в исследовании? какой % клиентов сталкивается с этим? насколько эмоционально заряжена боль? какой потенциальный LTV у клиентов с этой потребностью?

**2. Content-Market Fit (30%)** — соответствует ли проблемам, которые решает продукт? есть ли уникальный инсайт из клиентского исследования? есть ли клиентские истории в поддержку? естественно ли это ведёт к интересу к продукту?

**3. Search Potential (20%)** — месячный объём поиска? конкурентность темы? есть ли длиннохвостые возможности рядом? интерес растёт или падает?

**4. Resource Requirements (10%)** — достаточно ли экспертизы для авторитетного контента? какое доп. исследование нужно? какие ассеты (графика, данные, примеры) понадобятся?
